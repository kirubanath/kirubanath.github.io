What the work taught me

The agent is the small part of a system. The rest is evaluation, memory, retries and tracing. Each of these notes cost at least one bad afternoon.

A judge from the same family is a character witness.

Agents sometimes wrote code so wasteful that the server ran out of memory and a whole run was lost. I added a judge to read every solution first. It did not help until the judge and the agent were on different model families.

You cannot talk to every model the same way.

GPT models did best with the context first and the instructions after. Claude models followed an instruction better when it came with the reason. I know people like both.

Sometimes the right instruction is "check your work less".

We had about 24 hours per problem. Lighter validation meant a slightly noisier score and many more experiments. More ideas were worth more than steadier scores.

A long run has many ways to die.

Rate limits and server errors, mostly. So every model call went through one function that retries and waits longer each time, and every step was saved so a run could resume where it stopped.

Show the agent its best and its worst.

An agent learns little from a list of everything it has tried. Each new attempt saw one very good solution, one very bad one, and a short summary of the rest.

What production taught me

If you cannot look at it afterwards, do not ship it.

Trace every model call. When an output reads wrong, you want to see what the model was given and what it wrote. The alternative is a séance.
